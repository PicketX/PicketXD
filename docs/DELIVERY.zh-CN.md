# 持续交付路线

> [English (default)](DELIVERY.md) | 简体中文

用户于 2026-10-15 授权分阶段持续交付，直至具备可用四层控制、七层授权和较为易用的管理端。既定决策内的常规实现、测试、评审及集成持续推进；重大产品或安全取舍集中确认。这是执行授权，不代表未完成功能已经存在，也不是后台任务。

| 增量 | 交付物 | 验收边界 |
| --- | --- | --- |
| M1.3A | 共享规划层到私有 M0 夹具的编译器 | 显式时间转换、来源记录、替换校验；无内核副作用 |
| M1.3B | 已确认的隔离应用/撤销生命周期 | 准入/DNAT 原子提交、实际发出回执/读回、累计历史、精确严格清理重试与空所有权 |
| M1.3C | 边界驱动及内核契约验证 | 旧版本/取消保护；原有 17 项 M0 测试及已批准桥接验收类别，实际双栈报文证据 |
| M2 | 可部署四层闭环 | 有版本的权威配置、Agent 生命周期及恢复、认证的 Controller 同步、真实应用状态、独立过期与撤销 |
| M3 | HTTP/HTTPS 七层授权 | 可信既有入口与受限本地决策 API；逐请求路由/身份校验，异常拒绝集成测试 |
| M4 | 门户与管理端 | 来源/资源/期限申请、基本审批、Grant/撤销、Agent 状态与诊断；中英文、无障碍及响应式流程 |
| M5 | 基本可用版本 | Gitea 浏览器/Git/SSH 场景、四层/七层联合决策、重启/中断、静态二进制/部署指南及用户流程验收 |

M2–M5 是交付目标，接口尚未冻结；实现前依据已批准产品及配置基线细化。七层首版使用可信入口集成；原生 SSH/数据库代理、NFQUEUE、透明代理及 Agent TLS 终止继续延后。四层准入与应用认证保持独立。

各增量在 PR 中记录测试、实际 CI 证据、已知边界和下一入口，满足必需检查/评审后合并。不能把计划或模拟结果描述成已实际实施。中央 [M1.3 设计](https://github.com/PicketX/PicketX/blob/9d53b13e2d8a805b2a7b2f3a8ad957fcf84ea12d/docs/superpowers/specs/2026-10-15-core-m0-bridge-design.zh-CN.md)约束全部三个桥接切片；分批交付不删除任何验收要求。
