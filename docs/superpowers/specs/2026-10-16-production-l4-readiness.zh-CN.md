## 下一目标

单一静态权威的主机 Agent，能够在实际命名空间内完成完整受支持策略的校验、应用、确认、重载和恢复。先覆盖明确的 host INPUT/原始目标 TCP/UDP，IPv4/IPv6 同等支持。沿用固定 `inet picketx` 所有权边界及现有 Go Netlink 依赖。Controller 传输、容器发布/FORWARD、网关路由、七层与管理端仍属后续增量；保留 `prepare` 不修改内核的行为。

## 运行实现必须落实的决策

| 边界 | 必需行为与评审证据 |
| --- | --- |
| 命名空间与进程归属 | Agent 生命周期内持有 namespace 描述符和单实例锁；副作用前复核 namespace/boot/runtime 身份。仅锁住某个缓存旁的文件，不能阻止使用另一状态路径的进程写入同一张表。 |
| 表归属 | 修改前先检查。已有外来或无法识别的 `inet picketx` 时拒绝；表名本身不是接管依据。持久安装身份必须匹配内核标记及完全可理解的实际结构，不加入无条件接管/flush 开关。 |
| conntrack 归属 | 用运维明确保留的分配及冲突检查替代 `TestMark`；mark 归属与策略身份分开。支持相同 tuple 的 Resource/Endpoint 重建前，先规定退休/复用：旧 graceful 连接不能悄悄成为新授权。 |
| 持久化 | 已接受期望与已应用历史分开。发送事务前持久记录应用尝试，保留此前确认的所有权；只有 ACK 和语义读回后才持久记录确认。rename/fsync 结果不确定属于故障。 |
| 应用不确定 | 在发送、ACK、读回、日志发布之间崩溃，必须表现为 unknown/recovering。pending 期望快照本身不能授权删除 conntrack；恢复需要实际所有权/结构证据，保留可能仍相关的历史。 |
| 时间边界 | 原生 allow 到期保留绝对期限。进程在定时器触发前消失，未来 deny 或 strict 截止仍须有效；单靠 Go 定时器不够。评估内核预设边界或明确声明的目标 fail-closed guard，不悄悄改变 graceful 语义。 |
| strict 恢复 | 先确认限制策略，再范围删除；跨到期、中间应用及清理失败保留累计历史。dump 中断、部分删除和剩余目标仍报错；运行路径尚未证明的 strict 要求须拒绝。 |
| 明确撤回 | 删除最后 Grant 保持保护；删除最后 Binding 仅在有效替换后撤回自有保护。mark 退休与同名/UID 重建一起定义，期望撤回不是安装回执。 |
| 状态与关闭 | 分开期望版本/哈希、applying/confirmed/unknown/recovering、清理待办、观察时刻及错误。重启不能从磁盘恢复“实际已确认”布尔值；正常停止不悄悄撤掉服务保护。 |

已固定的 nftables 库暴露规则 `UserData`，其 table/chain 模型没有等价所有权字段。可评估专用无 hook owner chain 和标记规则，并通过结构读回、命名空间测试验证。标记是在可信 NET_ADMIN 所有权下检测冲突，不能对抗另一个特权进程。

## 实施顺序与验收

1. **所有权与崩溃契约：** 确定表标记、namespace 锁、mark 保留/生命周期和持久尝试/确认结构。测试区分外来表/标记、缺失/损坏日志、另一状态路径、同 boot 崩溃及新 boot 恢复。暴露修改内核的命令前逐个测试崩溃点。
2. **通用内核引擎：** 仅将必需机制迁到运行类型后，保留语义读回、实际发送时刻的绝对期限，以及所有既有夹具适配器/测试。抽取后记录真实内核证据。
3. **静态主机执行循环：** 接通已接受配置、应用日志、apply/confirm 与边界驱动。非法重载保留上次确认规则；不确定结果不能报告 confirmed，也不能开始破坏性清理。
4. **独立进程验收：** 部署命令上的双栈实报文、到期前后重启、未来 deny 前进程消失、受支持 strict 的失败重试、明确空撤回、无关表/连接保留。新增必需场景与既有 43 项一起强制验收。

首个运行增量必须明确支持哪些连接处理/时间边界要求。分阶段开发时可以按能力拒绝；不能悄悄接受进程丢失后无法兑现的契约。本简报后先落实运行契约并形成聚焦的可执行计划，再编写产品代码。
