# Human approval / kernel conjunction

## Intent and scope
Extend the existing native conjunction, not create another executor. Pin Core
b79e242926c67d931537c160333008df699fa598 (PR32 accepted main). Prove real human
password/SCS sessions, independent narrowed approval, durable Grant/audit, official
gRPC, actual Agent confirmation, nftables, Nginx and application in one run.
No production, public API, dependency or license boundary changes.

## Design
Keep the original 18 cases. Add a focused browser helper using independent human
requester/admin contexts and existing UI/API. Provision random private-file users
through the actual password-hash CLI. Request both named web/sibling entries on
IPv4/IPv6, approve only web and shorten each absolute deadline. Pending/rejected
requests must not open access or consume publication revisions. Read back actual
request/Grant/audit provenance; requester is never the packet identity.

Wait for actual desired/applied revision/hash and Controller-received Agent APPLIED
report before traffic probes. Both families must reach the real app only after
approval; sibling remains closed. Revoke IPv4 while IPv6 remains allowed, prove
established IPv4 HTTP denial; then IPv6 expires without a publication change and
both new-flow denial and established IPv6 HTTP403 must hold. Reach the app through
a real browser in the new workflow too. Capture real 375/1440 workflow screenshots.

The fail-closed report gate requires every old/new named case and complete sanitized
workflow provenance; malformed/self-approved/extended/decorrelated records fail.
Unit reports are labeled unit-only and cannot replace native evidence. No route
stubs, synthetic reports, clock changes, authentication bypass or skipped gates.

## Constraints and boundaries
IPv4/IPv6 equal; source CIDRs explicit; Grant union and independent absolute expiry;
approval/publication is not application. Keep all existing Linux/systemd gates.
Local Unixgram EPERM is known and must be reported, not suppressed. Existing
loopback/plaintext/graceful test boundaries remain; OIDC, production TLS and full
product/release acceptance are not established by this increment.

## Alternatives
Reusing Core's standalone browser helper cannot prove Agent/kernel conjunction;
replacing the original cases loses overlap/forgery/expiry coverage. Extend the
existing native fixture with an isolated helper and strict evidence gate instead.
