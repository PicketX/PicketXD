## 恢复与容量边界

仅实际现场确认的映像计入持久历史。已安装未来 Grant 可无进程激活，算潜在所有权。pending 保留旧历史与独立候选，现场认出候选才合并，认出旧映像不记被拒候选。v4 当前映像须被覆盖，范围/shape/台账/当前成员损坏均拒绝。

首次覆盖完整；v1/v2/v3 可读，v3 只能补已知当前映像，同 boot 永不推断完整，no-op 也不能重建历史。记录式清理拒绝不完整覆盖。验证新 boot 且旧表缺失才清空历史范围，保留退休 mark 和逻辑基线；此为注入单测证据，不声称真实重启。旧二进制拒绝 v4，不支持原地降级。

上限4096目标、65536来源/端点成员、8MiB JSON，日志仍64MiB。效果前预览，超限或 context 不兼容先于 mark/nft 拒绝；不按过期/清理裁剪、不复用 mark。同 boot 可信 context 迁移须显式部署路径。被拒物理替换后，现场当前 mark 可已退休：记录式清理在 Session 现场确认下接受精确已知绑定，不反退休/重分配；映像式构造器仍要求当前 mark 活跃。

清理不写日志/nft。沿用 M2C6 当前独立权限/deny、完整双族预检、原始元组/zone/opaque ID 精确 ACK 删除、最终回读及失效/重开。可信特权写入独占、正确时钟及文件系统持久性仍为前提。范围内成功不承诺自动 strict 调度或持久完成。

## 审查、决策与延期

一次全新整分支审查：无 Critical、两项 Important、一项 Minor。两项先复现 RED 后一次修复并通过完整409案例：TestHistoryNarrowTargetWithinTrustedScope（首次应用/旧版迁移）和 TestHistoryRejectedPhysicalReplacementRetiredCurrentCleanup（台账不变、原构造器限制保留）。修复版原生门禁覆盖两项，没有二次审查替代回归证据。

按顺序作出的决策：

1. 紧凑来源/端点/物理身份替代重复映像，因续期 ID/期限不决定旧连接所有权。代价：维护独立有界校验器，当前完整输入/基线保留。
2. 旧 v3 始终不完整，因丢失历史无法重建。代价：明确建立新 boot/部署覆盖前，拒绝记录式清理。
3. 审查保留原生结果/版本对应判断，要求完整原始 CI 和精确树。代价：兼容结论仅限记录 runner，不作本地 namespace 声明。
4. 审查保留真实 reboot 判断，仅声明注入 boot 身份/旧表缺失。代价：真实重启需专门环境。
5. 审查保留三项原有 Minor，保持不变。代价：低层 Plan 须构造、要求正确时钟、拒绝历史纪元边缘。
6. 审查保留自动 strict/凭据，留后续增量。代价：记录式清理不是 strict 生命周期承诺。
7. 验证并推送代码后本地执行连接中断，改用带预期 head 的 Git Data 完成文档/证据发布，从日志核对报告/原始流/构建元数据。代价：修复版 ZIP 未独立复算，本地最终文档和临时审查目录清理无法核验；明确仅声明上传/API 摘要一致。

延期 Minor：成员超限夹具含零值，先因无效前缀拒绝，未直接验证计数限制；仍需有效成员计数/8MiB/Owner容量效果前拒绝的直接回归。运行时限制存在，但不作这些直接覆盖声明。三项原有延期：零值低层 Plan 绕过构造器；time.Now 单调读数限制真实墙钟回退检测；首个正 Unix 秒的保守时间戳拒绝。

下一步接入 strict 准入、协调/边界恢复及持久完成证据，再暴露自动 strict。Controller、容器/FORWARD、L7 和管理端按[交付路线](../DELIVERY.zh-CN.md)推进。
