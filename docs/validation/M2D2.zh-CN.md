# M2D2 — 管理端与内核联合验收

本测试连接原来分别验证的链路：真实 Chromium → React 管理写入 → 数据库权威
API/SQLite → 官方 gRPC → 实际 Agent nftables → Nginx auth_request → HTTP 应用。
Core 固定版本另行检出，保留 Apache/GPL 边界，不修改 Agent 生产依赖。

在具备 sudo、网络命名空间、iproute2、Nginx auth_request 和 SQLite C 编译工具的
一次性 Linux 中，用固定 Core 的 Node/Go 版本安装锁文件依赖，执行 Web
typecheck/lint/build，安装 Playwright Chromium 并设置 PLAYWRIGHT_BROWSERS_PATH。
随后运行 `PICKETX_CONSOLE_KERNEL_TESTS=1 scripts/test-console-kernel.sh /绝对/Core路径`。
编译在提权前完成；实际测试只在新网络命名空间内执行，权限不足直接失败，不跳过。

验证包括双栈独立授权、未授权端点、Grant 并集、最后一条撤销、独立绝对期限；
同一已建立连接上的路径/方法/Host/伪造头拒绝必须返回 403，且不能到达应用。
新连接的传输层拒绝与 HTTP 拒绝分开记录，先有服务存活的正向对照。
同时核对实际 Agent 期望/应用版本及摘要，以及管理 API 接收的真实 gRPC 报告。
审批或保存不等于已经应用。浏览器必须真实访问应用，并保留审计与双尺寸截图。

保留原有18场景，另加真实密码/SCS人员申请与独立缩限审批：显式双栈来源、
同时申请web/sibling而只批准web，并缩短固定绝对期限。待批/拒绝不发布权限；
核对实际持久Grant/人员审计与Agent确认。IPv4撤销时IPv6继续可用，随后IPv6
不经重新发布自然到期；已建立HTTP连接也须拒绝。新流程真实浏览器访问应用，
并保留375/1440页面截图，不能用独立Core测试代替联合内核证据。
每个人员场景绑定精确审批/撤销版本，保留完整单资源命名Grant和精确审计操作/版本。
每场景前后执行双栈Nginx未受保护健康对照，并拒绝信号终止服务，防止宕机冒充拒绝。

证据输出在 `artifacts/console-kernel/`：源码/二进制/内核身份、逐场景记录、实际
Agent 状态流、脱敏日志及截图。证据门禁单元测试中的虚构数据仅验证门禁，不能
当作内核验收。已有 Go/race/vet/build、91 个原生门禁及 systemd 用例继续必需。

本段使用 graceful，不宣称撤销立即重置 TCP；严格撤销由原有原生测试覆盖。
环回明文是隔离测试拓扑，不代表生产 TLS 部署。基础配置用独立访问密钥，新增
申请审批用真实人员密码会话；OIDC、账户生命周期与生产部署仍为后续工作。
HTTP测试应用不是实际Gitea HTTPS/SSH部署，也不代表整个产品验收完成。
只有真实 CI 成功后才在交付检查点和 PR 记录完成；本说明本身不是成功证据。
