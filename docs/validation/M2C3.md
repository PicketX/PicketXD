# M2C3 durable mark reservation record

> English (default) | [简体中文](M2C3.zh-CN.md)

Date: 2026-10-16. Base: PR #6 / main `201b79db07942f15bda8d473441d6aee248e75e7`, tree `de1ac430f3afda963276eae0bf886c5e7e9c69fb`. This increment reserves marks durably; it does not install traffic rules or write/delete conntrack entries in production.

## Implemented

- `markstate` validates an explicit nonzero full-u32 reservation of 1..4096 values and computes deterministic append-only assignments. Withdrawn or physically changed targets retire their marks forever; recreation gets a fresh mark. Duplicate keys, corrupt history, range change, any unallocated occupied reserved value and exhaustion reject the whole candidate without partial results.
- `hostpolicy.MarkTargets` preserves Resource UID and hashes complete context/physical matches independently of Grant lifetimes and Binding provenance. It reads complete inventory, so inactive targets still reserve identities.
- `hostowner.ReconcileMarks` runs under the namespace singleton and journal locks, verifies exact marker-only structure before/after complete IPv4/IPv6 CT occupancy scans, and durably publishes the complete ledger before returning assignments. Unchanged desired state still scans; publication failure faults the session until reopen. Returned state is independent.
- One pinned descriptor-relative owner journal upgrades v1 to v2 when first reserving marks; v2 requires a valid ledger, including Agent binding. New boot retains reservation/retirement history while establishing a fresh marker epoch. Old binaries reject v2. Journal bound is 32 MiB.
- Namespace-bound raw CT observation streams at most 64 MiB per family and preserves strict status/completion/interruption/sequence/PID/type/family checks. NFT observation retains its 4 MiB bound. Production performs no CT writes or deletes.

## Decisions and remaining boundary

Ruling: raise the journal bound from 8 to 32 MiB instead of narrowing previously accepted identities; this preserves promised capacity at a higher bounded memory/I/O cost.

Permanent tombstones intentionally trade recycling for no stale-flow authority reuse; the installation fails explicitly at reservation exhaustion instead of silently recycling. Observing known numeric marks is not authentication: operator-reserved values and trusted NET_ADMIN ownership remain required against another privileged manager. A current numeric occupancy snapshot is not linearizable against concurrent foreign writes.

MarkStatus is a durable reservation result, not a kernel apply/cleanup receipt. Existing marker structure and `prepare` stay nonfiltering. The next engine must consume the ledger, add a versioned applied-rule structural contract and durable attempt/history recovery, and prove restrictive boundaries during process loss before exposing a production enforcement command. Strict execution, L7 and management remain later work.
