# M2D2 — console / kernel conjunction

This native test joins previously independent acceptance chains. It runs the exact
Core commit in `integration/console-evidence.mjs` as a separate Apache checkout;
the GPL Agent keeps its existing module pin. No production package changes.

## Reproduce

Use disposable Linux with Go from go.mod, Node from the pinned Core .node-version,
SQLite C build tooling, iproute2, Nginx with auth_request, sudo and network namespace
capability. In the pinned Core apps/web directory run `npm ci`, typecheck, lint,
build and `npx playwright install --with-deps chromium`, with an explicit
`PLAYWRIGHT_BROWSERS_PATH`. Then in this Agent checkout:

```sh
PICKETX_CONSOLE_KERNEL_TESTS=1 scripts/test-console-kernel.sh /absolute/pinned-core
```

The script builds before elevation, then starts a new network namespace. Missing
capabilities, missing browser, missing cases and skipped execution are failures.
It does not install dependencies itself or modify the host firewall. Temporary
private credentials/SQLite live in a unique directory and are removed after use.

## What is checked

- Chromium session → real React publication and structured Grant issue/revoke →
  database-authoritative API/SQLite → official gRPC → actual Agent executor.
- Exact desired/applied generation and hash, plus the actual report returned by
  the management observations API; acceptance alone is not application.
- IPv4/IPv6 fresh-connection default denial, independent grants, endpoint isolation,
  overlap union and last-grant removal. Unmanaged endpoints remain reachable.
- Real Nginx auth_request → real application; path/method/host/forged-header denial
  on the same established connection. Denials must have no application hit.
- Distinct absolute IPv4 and IPv6 deadlines. IPv4 expires while IPv6 remains allowed;
  later both new flows fail and both established flows receive HTTP 403.
- Actual browser application navigation, management audit reasons and desktop/mobile
  node pages. No API routing stubs, synthetic Agent reports or simulated kernel.

`artifacts/console-kernel/` contains source/binary identity, kernel/toolchain identity,
per-case packet/HTTP observations, actual Agent status stream, sanitized process logs
and screenshots. `console-evidence.test.mjs` uses explicitly labeled *unit* reports
only to test the fail-closed validator; those fixtures are not native evidence.
Existing full Go/race/vet/build, 91 native gates and systemd cases remain mandatory.

## Boundaries

Loopback plaintext is an isolated fixture, not a production TLS deployment. Existing
ingress owns TLS and forwarding. Graceful revocation does not promise TCP resets;
L7 rechecks each request. Strict recovery remains in the separate existing native
suite. Admin uses an independent access key/session, not human OIDC or approval.
Human login/request/approval and production deployment remain subsequent work.
Native execution evidence is recorded in AUTONOMOUS_DELIVERY and the PR only after
the actual CI run has passed; this document alone is not acceptance evidence.
