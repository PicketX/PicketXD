## Implemented and local evidence

`internal/hostpolicy` consumes shared immutable plans with trusted authority/context bounds. It validates complete selected inventory before projecting active members, supports arbitrary canonical IPv4/IPv6 TCP/UDP targets, and preserves Resource/contribution UID, Binding provenance and independent absolute lifetimes. Complete inventory retains future/expired/revoked members; last Grant expiry retains protection; last Binding removal can yield empty desired output. Nil, unknown-Agent, authority/context/namespace mismatch and unsupported selected dormant targets are refused. Returned nested data can be mutated independently; concurrent evaluation does not share mutable results.

All six new test groups failed against compiling stubs before implementation, then passed. They include actual `configuration.Decode`/`Compile`/`Replace`, source ranges, separate same-ID Grant/Deny, future denies, NotBefore/exclusive expiry, permanent members, UID recreation, withdrawal, trusted-scope rejection and mutation/concurrency checks. Go 1.27.0: **89 top-level tests pass**, zero failures/skips; full race/vet/build and static preparation/restart/invalid-publication smoke pass. Integration packages compile.

The existing host fixture now converts hostpolicy output to its private kernel input only inside integration tests. Required `TestHostPolicyCompilerPorts` adds real dual-stack TCP/8001 and UDP/8002 allowed-source, unrelated-source denial and unrelated-service controls. All prior 50 required cases remain; 51 are now mandatory. Native execution passed as recorded below.

## Execution decisions

- Preserve shared Core's context contract: endpoint addresses narrow physical target matches; a Binding declaration cannot contradict its full resolved context. The initial narrowing test was corrected before implementation. Cost if misunderstood: rejecting a valid narrow endpoint or accepting widened runtime facts.
- Keep future denies in desired inventory and boundary evaluation. Their presence does not claim process-loss-safe installation. Cost if misused as a kernel receipt: restrictions could be omitted when the Agent stops; the production apply boundary remains unavailable.

## Remaining production boundary

This compiler allocates no conntrack marks, performs no Netlink effects, publishes no applied journal and returns no confirmation receipt. Marker-only ownership and `prepare` stay unchanged. A production engine still needs a versioned structural contract, reserved mark allocation/retirement, durable applied history and process-loss-safe restrictive boundaries before exposing host enforcement. L7 and management remain later work.
