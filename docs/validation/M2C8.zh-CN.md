## 规则、恢复及运行代价

graceful v1 编码/哈希/默认/runtimeKey 不变。strict imagev2 新增同 Agent/context 台账中最多4096个排序已知 mark，含退休别名；未知/跨 context 别名在应用/恢复/清理时拒绝。journal 仍为v4，旧二进制拒绝 v2 映像。退休 mark 保留当前独立允许连接，永不复用。

strict 的 deny 和当前成员/期限先于共享已知 mark 已建立连接准入；新 TCP SYN 另需 conntrack NEW 才写 mark。UDP 按当前成员判断并标记。每次协调确认真实规则、完整双族清理、再核对一致的 desired 代数/哈希及先前最早边界；最终快照跨 validUntil 不得确认。别名和守卫计入8192规则、映像/历史8MiB、日志64MiB上限。

真实 run39004655614 观察到删除后 IPv6 旧 TCP 的新字节 q 仍回显，内核 mark0 原始方向为服务18443→客户端53155/47003；run39004816741 的显式反向 UDP 在旧代码上也失败。strict 现于全部原始目标分发后添加“实际保护目的端点且 reply 方向”的 DROP，拦截反向重建，保留 original 方向范围外 DNAT。新增布局回归先观察 RED 再修复，以上原生门禁验证实际内核。

**strict 保护本地地址/端口须专用于服务，不要将主动出站客户端绑定到这些源端点，其入站回复可能被拒绝。** 每个保护端点额外一条规则。清理保留未标记/无关 conntrack 记录；守卫仍会拒绝发往预留服务端点的报文。不修改全局 conntrack sysctl、OUTPUT 策略，不做全表 flush。

每个 poll 和已知边界重复完整双族扫描/读回；没有缓存/持久完成凭据。进程缺席时内核期限拒绝失效报文，但不删除 conntrack。若清理前权限恢复，仍存标记 TCP 可能恢复；仅承诺成功清理的旧 TCP 不靠无标记重建复活。UDP 无连接，新有效流可在重新授权下恢复。不承诺 TCP RST/对端立即通知。同 boot 模式/context 迁移需要明确兼容部署。可信特权写入独占、正确时钟、独占预留 mark 和持久文件系统仍为前提。

## 评审、决策与延期

一次全新整分支审查发现0 Critical、1 Important、无新增 Minor。重要的最终快照越界窗口由 TestStrictFinalSnapshotBoundaryCannotConfirm 独立重现，RED→GREEN 后跑完整套件。CI 另暴露反向重建及已有短墙钟夹具的调度敏感失败，均先观察和定位再修正，未用二次评审替代回归及原生证据。

按先后顺序的决策：

1. 当前成员后共享已知已建立连接链；代价：额外链/别名校验器，历史 mark 规则线性有界。
2. 拒绝同 boot 模式迁移并保留 graceful/runtime 身份；代价：需新兼容部署，自动迁移延期。
3. 每次 strict 回调均清理、状态只作观察；代价：每次 poll/边界完整双族扫描，无进程不删除。
4. 确认只证明当前授权及观察清理，不证明错过的权限间隔完成撤销；代价：清理前恢复权限可能使保留标记 TCP 恢复，UDP 仍无连接。
5. 评审保留原生/CI/归档/版本/最终验收判断，根执行者独立核对；代价：仅已测 runner 兼容，不作本地特权声明。
6. 评审保留原有问题，维持并明确报告；代价：底层 Plan 必须用构造器、依赖正确时钟，epoch 边界和容量回归覆盖缺口仍在。
7. 坏发布到期单测改为观察 live 后推进注入时钟；代价：此单测不测实际延迟，真实内核/进程期限门禁仍必需。
8. strict 端点预留及 reply 回退拒绝；代价：客户端不能使用这些本地源端点，每端点多一条规则；graceful 和无关 CT 记录不变。

延期 Minor 共四项：底层零值 Plan 绕过（真实 Session 用构造器）；生产回拨检测受 time.Now 单调部分限制；首个正 Unix 秒限制；M2C7 有效成员数量/8MiB/Owner 效果前容量回归夹具待补（旧零值夹具在数量上限前就被拒绝）。未暗中修复或声称已覆盖。
