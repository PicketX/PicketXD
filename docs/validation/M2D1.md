## Observed behavior

The real Agent process accepted authenticated scoped intent, installed owned INPUT
rules and allowed IPv4/IPv6 TCP/UDP. Removing only Grants denied fresh flows while
established graceful TCP remained. Fresh Grants reallowed admission; a complete empty
target list withdrew protection. Wire APPLIED reports followed native confirmation.

The strict remote test applied independent absolute deadlines, then stopped the
Controller and SIGKILLed the Agent. Native dual-stack TCP/UDP expired without either
process. Offline restart restored revision1 LKG and confirmed cleanup without extending
permissions. The actual pinned Core/SQLite process drove actual Agent revisions1→2→3:
allow, grant-only removal/default deny, complete withdrawal, each checked with four
real packet probes; both processes shut down cleanly. Remote declarative namespace IDs
were distinct from the held local namespace.

## Behavior, rulings and remaining work

See [deployment](../../examples/controller/README.md). Exactly one source is selected.
Remote v2 LKG stores wire envelope and derived policy, bound to provider type, expected
authority/Agent, local scope and transport settings; static v1 cannot be adopted as remote.
Invalid input/outage/restart never refresh absolute deadlines. CA binding records configured
paths/settings; changing CA contents at the same path is an operator trust change.

Ruling: reuse the existing configuration compiler instead of a parallel executor. This
preserves existing strict/recovery behavior but conservatively rejects complex inventories
outside the supported single-host-profile/UID subset. Ruling: an equivalent durable inline
ledger substitutes for unavailable cloud skill helper scripts; the cost is manual checkpoint
consistency, addressed with exact head/tree/CI evidence. Nonblocking deferred review suggestion:
explicit malformed future/revoked contribution variants; conversion already validates them unconditionally.

A full empty snapshot withdraws protection; grant-only removal retains default deny.
Token revocation stops synchronization, not permanent cached access: confirm restrictive
intent before unenrollment or use bounded Grants. Cacheless startup waits; offline LKG
confirmation proves accepted local intent, not the latest unseen Controller intent.
RECEIVED/APPLIED/FAILED are authenticated Agent assertions, with no protocol heartbeat,
report acknowledgement or independent Controller proof. Send failure can follow successful
native application. Systemd readiness remains a one-time event. Existing strict pre-cleanup
failure retention, boot gaps and missed-interval durable revocation limits remain.

Next: database-authoritative management persistence/API/login/RBAC (no file poll overwrite),
trusted HTTP ingress authorization, live React pages and browser/proxy/application acceptance.
