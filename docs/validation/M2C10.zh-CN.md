## 服务行为与审查

真实 systemd255 仅替换测试路径/状态/轮询并添加 NetworkNamespacePath，保留模板全部能力/文件系统/套接字/重启设置。核对实际能力仅 CAP_NET_ADMIN、NoNewPrivileges、0700 私有状态、目标命名空间准确且不同于测试驱动。IPv4/IPv6 TCP/UDP 回显成功。SIGKILL 后自动以新 PID 重启，generation、策略 hash 和镜像标识不变。无效原子发布保留已接受流量；移除两个 Grant、保留 Resource/Binding 后拒绝新双栈 TCP/UDP。显式停止保留拒绝规则和两个状态文件；手动重启后拒绝、generation/镜像及 owner/desired JSON 字节均不变。

独立审查无 Critical/Important 问题。唯一 Minor 是重复运行在预检查失败时可能留下旧成功归档，已通过受控失败管理器命令复现，修正为权限/管理器检查前清除报告和日志，再独立复验：非零失败且两旧文件均不存在。无开放审查问题。离线语法检查在模板缺失时观察到失败，添加后通过，但不构成原生证据。

## 边界

默认示例仅双栈回环 graceful 主机 INPUT/原始目标 TCP/UDP。指南说明全新 strict 选择，但新增服务场景使用 graceful；既有 strict 原生门禁保留。服务权限限制在替换测试路径/状态/轮询并添加 NetworkNamespacePath 的全新隔离环境验证，不安装生产宿主防火墙。active 不等于就绪，network.target 不证明时钟/地址/实际应用；新启动在规则建立前有窗口。跨未观察间隔持久撤销、Controller 同步、容器/FORWARD、L7 和界面仍待实现。M2C9 的 strict 清理失败成本及四项继承待办不变。
