## 服务行为与审查

既有六个真实管理器场景保留。新增三项：恢复确认缓存但当前发布无效时保持 activating，Requires/After 依赖不启动；有效同代发布后真实 READY 放行依赖标记；启动超时后停止进程，拒绝及 owner/desired JSON 字节保留。仅超时阶段把60秒缩为2秒，权限限制、NotifyAccess及重启策略保留；观察超时终止/回收后取消待重试任务。既有 strict 原生门禁继续必需。

初始 [run68](https://github.com/PicketX/PicketXD/actions/runs/39048608123) 完整 Go/套接字/内核及前六服务场景通过，在干净停止后的 reset-failed 初始化处失败。上游 systemd255 的 ResetFailedUnit 故意不加载已卸载单元，未引用的 inactive 单元可被回收。两处重置改为 active/已加载时执行，完整 run69 通过，没有忽略初始化失败。

独立审查发现并修正超时观测竞态（Result 可早于进程回收）及“仅启动阶段”措辞；有界 SubState/MainPID 等待与双语表述已复核。随后卸载顺序修正也经审查，无开放 Critical/Important/Minor。CLI 帮助/环境/once 回归在旧命令先观察 RED，再 GREEN；真实传输和消息顺序在完整 CI 通过。

## 行为与边界

须显式 --systemd-notify，独立 enforce/prepare 忽略 NOTIFY_SOCKET。缺失/格式错误环境和 --once 在命名空间效果前拒绝。先成功输出 JSON；通知错误使进程停止、保留规则。连接/写入各一秒期限，STATUS 固定文本不插入错误/发布内容，不依赖 libsystemd/C。既有权威确认且 desired.lastError/lastApplyError 均空后才发送一次 READY；当前发布无效而缓存镜像确认时不放行启动。数据报发送成功不代表管理器确认，由真实 notify 和有序依赖验收验证实际消费。

受保护应用须显式 Requires 加 After；不覆盖手动/外部启动，不保证全局开机默认拒绝。首次就绪后发布被拒绝可仍 active，须查看新 JSON/STATUS。不新增 READY=0、watchdog、健康端点、Controller 同步、容器/FORWARD、L7 或界面。最多等待60秒再按既有重启/速率限制处理，间隔大的超时可能持续重试。新增服务用 graceful，既有 strict 门禁保留；strict 清理失败成本和四项继承待办不变，跨未观察间隔持久撤销仍未完成。
