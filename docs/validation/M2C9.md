# M2C9: cleanup before strict replacement

> English (default) | [简体中文](M2C9.zh-CN.md)

Acceptance is pending. This bounded change covers the existing strict driver, not a new durable completion subsystem.

## Scope and context map

A retained strict image can expire while its process is absent. Applying a fresh permanent Grant before cleaning that image makes current independent-permission preservation retain old marked TCP. Before replacing an existing strict image, complete recorded cleanup against that actual retained image; then apply the candidate and perform current cleanup/readback as before. Failure or remaining flows prevent replacement. Initial marker-only startup skips the previous-image phase. Graceful behavior, journal/image schemas, dependencies and CLI configuration stay unchanged.

## Limits

This closes replacement-order recovery when the retained old image currently withdraws the flow. It does not reconstruct unseen publications, persist cleanup intent, or prove every unobserved permission gap. A future Grant already installed in the same retained image can restore permission before any cleanup observation; that existing boundary remains explicit. Previous cleanup has its own image identity and cannot be used as current desired enforcement proof. Existing independent current permissions are preserved.
