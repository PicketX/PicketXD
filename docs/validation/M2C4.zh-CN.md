新增九项必需观测：

- `AdmissionDualStack`：双栈默认拒绝、按来源允许、显式拒绝优先。
- `AdmissionAbsoluteTime`：绝对到期 `2026-10-16T07:34:10.950757727Z` 后，即使 Session 已关闭也拒绝新 TCP 元组；已标记连接继续可用；重开不延长有效期。
- `AdmissionFutureDeny`：无 Session/Go 定时器时，双栈在 `[2026-10-16T07:34:14.019634458Z, 2026-10-16T07:34:16.019634458Z)` 内拒绝，区间前后允许。
- `AdmissionUDPFutureAllow`：无 Session 时，双栈 UDP 在生效前拒绝、有效期内允许、到期后拒绝新元组。
- `AdmissionOriginalDNAT`：原始目标端口 18543 经 DNAT 到实际监听端口 18443，生产 INPUT 正确按原始端口判断；测试 NAT 表保留。
- `AdmissionRecoveryAndDrift`：实际待执行映像在确认保存失败后重开核验恢复；随后添加真实规则被拒绝，不改日志或替换表。
- `AdmissionAtomicRejection`：同批次畸形操作导致原子回滚，双栈旧允许规则保留；重开将 pending 裁定为旧映像 `a3d48ebe32aafdba45ed9678b495c9513cff32ccce1c7a5989dd854521caeaeb`。
- `AdmissionWithdrawal`：最后一个 Grant 消失仍默认拒绝；显式空 Binding 清单撤销保护，其独立空映像可恢复。
- `AdmissionProcessRecovery`：独立 helper 未 Close 即 SIGKILL，过滤保留；另一 Session 从完整现场确认同一映像。

完整测试名以 `TestOwnerKernel` 开头；见英文对照表。所有新增场景使用可丢弃子网络命名空间，显式 opt-in 后权限/初始化失败不会跳过。保留旧 55 项门禁及无关流量保护检查；生产代码不导入验证 fixture、不删除 conntrack 条目。

新鲜完整分支评审发现两个 Important、无 Critical，以及一个 Minor。两个重要问题及额外状态问题已按 RED→GREEN 修复并通过全套：

1. 保留贡献 ID 的端点迁移原先绕过替换检查。现要求 `hostpolicy.CompileInput` 保留完整不可变来源；映像重编译核验，并用独立持久基线跨撤销/重启保留休眠、撤销、未绑定成员及受信上下文。mark 发布前执行共享 `networkplan.Replace`。覆盖活跃、撤销、未绑定、新启动拒绝及新 ID 再签发。
2. 标记结构原先未做代数前后核验。现所有已配置标记/规则映像（包括不存在状态）均核验代数；回归通过 `nftKernel.Observe` 验证并发变更拒绝。
3. 首次 pending 发布失败，即使内存尚无应用记录，也明确报告 `unknown`。

[首轮真实 CI 38867017243](https://github.com/PicketX/PicketXD/actions/runs/38867017243) 如实失败：内核显式返回 bitwise BOOL 默认操作，固定编码器省略该字段。回归先失败再修复；只归一化 `NFTA_BITWISE_OP=0`，仍拒绝其他操作、畸形/重复属性和未知字段。修复后完整真实 CI 通过。

暂缓小项：预期时间范围从 Unix 正纳秒 1 开始，但当前实现保守拒绝 1970 年首个正秒内时间；现代策略不受影响，不对此特殊区间作兼容声明。

实施裁定与成本：每份映像（含空撤销）增加一条无 hook 的摘要计数器规则，以区分流量表达式相同的语义版本；固定库不能解码 byteorder ECHO，故在已持有命名空间连接上使用 Go 表达式编码及无 ECHO 原子 UAPI，再核验 ACK 和完整现场，增加少量 UAPI 维护成本；NFT dump 上限 32 MiB、映像/输入/基线各 8 MiB、组合日志 64 MiB，增加有界内存/IO，系统 socket 上限仍可能安全拒绝大事务；替换从最后已确认完整输入直接校验，未应用的中间发布可能需要显式新 ID。真实语义依赖已记录内核验证，兼容范围仅限该环境；系统时钟、特权写入独占、显式 mark 预留和文件系统持久性仍是前提，标记/摘要不是对 NET_ADMIN 的身份认证。
