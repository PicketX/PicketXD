## 复现

先运行无特权检查：

```sh
go mod download
go test ./...
go test -race ./...
go vet ./...
go build ./...
```

在可销毁、具备权限的 Linux 主机上，准备 `unshare`、网络命名空间、nftables/conntrack 内核支持以及 root 或免密码 sudo：

```sh
PICKETX_KERNEL_TESTS=1 scripts/test-kernel.sh
```

脚本先以 `CGO_ENABLED=0` 构建，再在隔离父命名空间执行预构建测试，保留失败结果。`ip` 仅用于测试网络故障诊断。运行适配器通过 Go Netlink 调用，不依赖 nft/conntrack 命令或 C 库。测试不使用宿主机防火墙表，不清空 conntrack。每个场景创建自己的执行、客户端、服务端命名空间，在施加策略前验证两条未过滤路径。

`artifacts/` 包含 `nft.json`、`ct.json`、`kernel.txt`、`go.txt`、`modules.txt` 和 `report.json`。CI 在失败时也归档证据。报告保留失败、跳过、不支持的区别和撤销计数；`Remaining=-1` 表示未确认或不适用，不能解释为清理成功且剩余为零。每个必需场景必须实际通过，缺失或跳过会使任务失败。

## 发现与边界

- 已测内核和固定 nftables 库支持拼接区间集合及元素原生超时。内部夹具的每个贡献使用独立集合，分开处理重叠和期限；这属于验证代码，不是优化后的生产策略编译器。
- 从绝对过期时间计算剩余期限，向下取整到内核毫秒。已过期或不足一毫秒的成员直接省略，避免意外变成无超时成员。
- 严格撤销与 NAT 场景的失权 IPv4/IPv6 连接观察到 `Selected=2, Deleted=2, Remaining=0`。有效的其他授权、无关未标记连接和独立 NAT 映射继续交换真实报文。
- conntrack 删除按所属标记、原始/回复元组、地址族和 zone 限定。vishvananda/netlink 先遍历一个地址族，再删除选中的条目，并不是任意内核条件的原子删除。遍历中断或部分删除必须报错，在可执行时再确认剩余条目。本阶段没有实现或选定事件流。
- nftables 仅允许新的 TCP SYN 建立新授权。已标记连接支持平滑过期；严格撤销先应用候选策略，再移除失权状态。删除不保证发送 TCP reset 或关闭应用 socket。
- 初始 IPv6 失败来自隔离夹具初始化：新网卡转发设置和邻居收敛。夹具在创建网卡前设置转发，安装永久测试邻居，并验证两条未过滤路径。测试网络损坏时，单凭拒绝不能通过。
- 故障注入验证 nftables 原子拒绝和 conntrack 部分错误报告；大量策略/连接、并发授权变化、广泛内核矩阵以及生产生命周期/恢复尚未测量。
- 夹具 DTO 表示预期的有效快照，不是生产 Grant 编译器。M1 必须在 Gitea 流程之前增加共享 Core 的权限并集、默认值和领域契约测试。Controller 通信、认证、事件、活动续期和 UI 不属于 M0。

## 最终评审跟进

独立评审发现两处证据缺口，已在修复阶段处理：集成辅助代码在失败断言前记录真实撤销计数，事件读取器保留历史 strict/NAT 失败记录；重启场景现在临近过期时重新应用仍有效的快照，并按原始期限检查两个地址族。运行 [38547705369](https://github.com/PicketX/PicketXD/actions/runs/38547705369)故意注入完整 TTL 续期，使 `TestRestartPreservesDeadline` 按预期失败，同时独立期限测试也失败。最终验收前已恢复正确后端。

暂缓的小问题：拓扑清理尚未集中关闭 echo 服务端已接受的连接。隔离测试进程退出后会释放它们；单进程反复运行测试时，需要同步管理 socket 和 goroutine 清理。这不是生产 Agent 的生命周期实现。
