## Service behavior and review

Real systemd255 starts the shipped unit with test paths/state/poll and an added NetworkNamespacePath, retaining all capability/filesystem/socket/restart settings. Acceptance checks only CAP_NET_ADMIN effective, NoNewPrivileges, private 0700 state and exact target namespace distinct from the test driver's namespace. IPv4/IPv6 TCP/UDP echo succeeds. SIGKILL triggers automatic restart under a new PID; generation, policy hash and image identity recover unchanged. Invalid atomic publication retains accepted traffic. Removing both Grants keeps Resource/Binding and denies new dual-stack TCP/UDP flows. Intentional stop leaves that denial and both state files. Manual restart retains denial, generation/image and byte-identical owner/desired JSON.

A fresh independent review found no Critical/Important issue. Its one Minor—preflight failure leaving stale success artifacts on repeat runs—was reproduced with a controlled failing manager command, fixed by clearing both report and journal before privilege/manager checks, then independently rechecked. Failure remains nonzero and both old outputs are absent. No review findings remain open. Offline syntax validation also observed the absent-template failure before the template was added, then passed; it is not native evidence.

## Boundaries

The shipped example is loopback-only graceful host INPUT/original-destination TCP/UDP. Fresh strict selection is documented but the new service scenarios use graceful; prior strict native gates remain mandatory. The unit's filesystem/socket/capability restrictions are validated in a fresh test namespace with test paths/state/poll and NetworkNamespacePath substituted, not by installing a production host firewall. Process active is not readiness, After=network.target is not synchronized clock/address/application proof, and there is a fresh-boot interval before rules exist. Full durable revocation across unseen gaps, Controller sync, container/FORWARD, L7 and UI remain incomplete. Existing strict cleanup failure costs and four inherited deferred items in M2C9 remain unchanged.
