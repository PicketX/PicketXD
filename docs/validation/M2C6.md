# M2C6: scoped production host conntrack cleanup

## Result and evidence

`internal/hostrevoke` provides immutable image/mark-bound selection, typed native evidence and the complete-confirm/scan/delete/reconfirm protocol. `hostowner.Session.RevokeWithdrawn` serializes it under the held namespace/ownership session and uses its actual current confirmed image. It performs exact original-tuple/zone/opaque-kernel-ID deletion, never a broad filter/flush, nft mutation or journal write. This is the cleanup engine increment; `enforce` remains graceful and does not invoke cleanup automatically.

All new cases run in disposable child network namespaces. Setup errors fail explicitly opted-in execution. Typed scans complete both families before deletion; errors produce no partial evidence. Selection requires historical source plus original physical target and exact durable mark binding. Current active permission union preserves flows independently of their old mark; deny wins. Absolute membership uses the shared Core validity rules.

Linux [v6.17 ctnetlink_del_conntrack](https://github.com/torvalds/linux/blob/v6.17/net/netfilter/nf_conntrack_netlink.c) checks original tuple (or reply if no original), zone and opaque CTA_ID before deletion. It does not atomically compare mark/reply/policy. The encoder always supplies the original tuple, explicit zone and observed ID; missing/invalid flow cannot become a flush request. Directional tuple zones are refused rather than treated as zone zero. Unknown top-level metadata is structurally bounded; unsupported protocols are outside TCP/UDP scope.

## Review and rulings

A fresh independent whole-branch reviewer found no Critical or Important issue in the held-Session path. It independently passed focused uncached tests and race tests, integration compile-only and diff checks; native behavior/artifacts and full-repository claims were reserved for actual evidence. No review fix pass was needed.

Deferred Minor findings (no production changes in this pass):

- A zero-value `hostrevoke.Plan` can bypass the constructor and produce empty success. The actual Session entry point always constructs through `New`, which validates its current image/ledger/history. Direct low-level callers must do the same; hardening the zero value remains deferred.
- The clock comparison detects backward injected wall-only times, but production `time.Now` values carry monotonic readings, so real wall-clock rollback is not detected by `Before(last)`. Membership is re-evaluated against serialized wall-time boundaries; no incorrectly scoped deletion was found. Correct wall clock remains an explicit prerequisite; actual rollback detection is deferred.

The existing M2C4 first-positive-Unix-second timestamp minor is also unchanged and deferred.

- Split the production cleanup engine from persistent strict lifecycle. Reason: cumulative durable historical images and strict admission/boundary scheduling need independent recovery proof. Cost: callers must retain older images, completeness is not inferred, and no automatic strict command/receipt is introduced.
- Keep kernel connection ID as four opaque bytes. Reason: the kernel compares its native identifier representation directly. Cost: the API does not promise a portable numeric/endian interpretation.
- Re-read time before effects and refuse crossed current membership boundaries or detected backward supplied times (with the production wall-clock limitation above). This detects stale runs but does not make deletion atomic with the wall clock. Cost: retry/reopen after an error; future scheduler integration remains required. Trusted privileged writer exclusivity and correct wall clock remain prerequisites.

History is bounded to 32 caller images and 32 MiB cumulative image JSON; each image retains its existing 8 MiB bound. Each family dump is at most 64 MiB, with at most 262144 typed flows per complete snapshot. Duplicate/malformed/incomplete evidence fails before deletion. Current marks must be active and every historical physical identity must match durable mark history, including retired incarnations. Invalid caller history cannot retarget a known mark.

An error during cleanup faults the Session and clears live confirmation until reopen, preserving the installed filter and durable journal. A successful Result is scoped counts only: `Selected`, acknowledged `Deleted`, separately `Absent` for ENOENT, and confirmed `Remaining`. No confirmation dump yields `Remaining=-1`; remaining entries, partial deletion and confirmation drift are errors. Successful cleanup does not become a persisted strict-mode promise.

## Remaining scope

Caller history is validated candidate ownership evidence, not proof all images were actually emitted or that the supplied history is complete. The Session always includes its current real image; historical Grant expiry does not discard ownership of an established graceful flow. Only validated historical sources/physical targets/marks can be selected.

The existing graceful admission image can retain established traffic; this primitive does not itself promise strict process-loss scheduling or prevent all connection resurrection. Next integrate durable cumulative ownership history, strict admission and reconcile/boundary recovery. Controller, container/FORWARD, L7 and management follow the [delivery route](../DELIVERY.md). Compatibility remains limited to the recorded real environment. Existing M2C4 epoch-first-positive-second timestamp restriction remains deferred.
